# What's new in Ketoy — 0.4.16-alpha

This release turns KBC screens from static layouts into **real,
interactive, idiomatic Kotlin**. You now write ordinary Compose — typed
ViewModels, `var` state, reusable components, `forEach` loops, a full
`Canvas` drawing surface — and it compiles to a signed `.ktx` bundle and
renders natively on-device. No new mental model, no server round-trips
for state changes.

## Coordinates

```kotlin
dependencies {
    implementation(platform("dev.ketoy.vm:ketoy-bom:0.4.16-alpha"))
    implementation("dev.ketoy.vm:ketoy-runtime")
    implementation("dev.ketoy.vm:ketoy-hilt")             // optional
    implementation("dev.ketoy.vm:ketoy-adapters-material3")
}
```

Drop-in upgrade from 0.3.x — everything below is additive.

## At a glance

| Feature | What you write in KBC source |
|---------|------------------------------|
| **Typed ViewModels** | `@KetoyViewModel` + `ketoyViewModel<T>()` + `StateFlow` |
| **Local Compose state** | `var count by remember { mutableStateOf(0) }` |

| **Spacing** | `Arrangement.spacedBy(12.dp)` |
| **Per-corner shapes** | `RoundedCornerShape(bottomEnd = 16.dp)` |

## Typed ViewModels

Write an idiomatic `@KetoyViewModel` with a real `StateFlow`, consume it
from your screen with `ketoyViewModel<T>()`, and read it reactively with
`collectAsState()`. Compose owns recomposition; KetoyVM owns the
lifecycle (the VM survives recomposition + config change, cleared with
the screen).

```kotlin
import dev.ketoy.annotations.KetoyViewModel
import dev.ketoy.runtime.compose.ketoyViewModel
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update

data class CounterUiState(val count: Int = 0, val loading: Boolean = false)

@KetoyViewModel
class CounterViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(CounterUiState())
    val uiState: StateFlow<CounterUiState> = _uiState.asStateFlow()

    fun increment() = _uiState.update { it.copy(count = it.count + 1) }
}

@KetoyEntryPoint
@KetoyComposable
fun CounterScreen() {
    val vm = ketoyViewModel<CounterViewModel>()
    val state by vm.uiState.collectAsState()          // `by` or `.value` — both work

    Column {
        Text("Count: ${state.count}")
        Button(onClick = { vm.increment() }) { Text("Increment") }
    }
}
```

### What compiles

| Area | Supported |
|------|-----------|
| **Declaration** | `@KetoyViewModel class X : ViewModel()` — plus constructor params for DI |
| **UI state** | Any `data class` — construct, read property, `copy(...)`, destructure, `is`/`when` over sealed hierarchies |
| **State holder** | `MutableStateFlow(init)`, `asStateFlow()`, `.value`, `.update { old -> new }` — real `kotlinx.coroutines` flows |
| **Consumption** | `ketoyViewModel<T>()` in the composable; `collectAsState()` via both `val state by …` and `state.value` |
| **Event methods** | Plain methods (`fun increment()`, `fun select(id: Int)`) called from `onClick`/callbacks |
| **Coroutines** | `viewModelScope.launch { … }` — suspend work in the VM scope, cancelled with the screen |
| **Suspend calls** | `suspend fun` methods; `repo.fetch()` lowers to a host capability |
| **DI** | Constructor-injected repository **interfaces** (host provides the impl) |
| **Compose effects** | `remember`, `derivedStateOf`, `LaunchedEffect`, `SideEffect`, `DisposableEffect`, `collectAsState` |

### Lifecycle

The VM instance is created on first `ketoyViewModel<T>()` resolution and
**cached** — it survives recomposition and configuration change (backed
by the screen's `ViewModelStore`), and is cleared when the screen leaves
(`onCleared()` cancels `viewModelScope`). State accumulates across taps
exactly as a native ViewModel would.

!!! note "Sealed UI state"
    A `sealed interface UiState { object Loading; data class Loaded(…) }`
    consumed with `when (state) { is Loading -> …; is Loaded -> … }` works
    — the runtime matches `is Loaded` against the sealed parent.

### Constructor DI (repositories)

Inject a repository interface; the host provides the real
implementation as a capability. The bundle only depends on the
interface — Room/Ktor/Retrofit never enter the sandbox.

```kotlin
interface CounterRepository { suspend fun fetchSeed(): Int }

@KetoyViewModel
class CounterViewModel(private val repo: CounterRepository) : ViewModel() {
    private val _uiState = MutableStateFlow(CounterUiState())
    val uiState: StateFlow<CounterUiState> = _uiState.asStateFlow()

    fun refresh() = viewModelScope.launch {
        _uiState.update { it.copy(loading = true) }
        val seed = repo.fetchSeed()                   // → host capability
        _uiState.update { it.copy(count = seed, loading = false) }
    }
}
```

Host side — register the implementation against the method's capability
ID (Hilt-friendly; the impl can call Room, the network, anything):

```kotlin
registerSuspend(COUNTER_SEED) { todoRepository.countAll() }
```

See [ViewModel & state](../viewmodel-state.md) for the full lifecycle.

## Local Compose state

For screen-local UI state you don't need a ViewModel — use plain
Compose state. Compose owns the snapshot and recomposition; KetoyVM just
creates the real `mutableStateOf` and reads/writes `.value`.

```kotlin
@KetoyComposable
fun Stepper() {
    var count by remember { mutableStateOf(0) }

    Column {
        Text("Count: $count")
        Button(onClick = { count++ }) { Text("+1") }
    }
}
```

Supported:

- `var x by remember { mutableStateOf(...) }` — read + write + `x++`,
  `x += n`, etc.
- Typed factories: `mutableIntStateOf`, `mutableFloatStateOf`,
  `mutableLongStateOf`, `mutableDoubleStateOf`.
- `rememberSaveable { … }` — survives recomposition **and** config
  change.
- State read inside a `Scaffold` slot / content lambda that captures the
  variable recomposes correctly.

## Reusable `@KetoyComposable` components

Extract a non-entry `@KetoyComposable` helper and call it from another
KBC composable — passing **callback lambdas** and **content slots**,
including ones that capture and drive local state.

```kotlin
@KetoyComposable
fun LabeledRow(label: String, selected: Boolean, onSelect: () -> Unit) {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .clickable { onSelect() },              // component invokes the callback
    ) {
        Text(label)
        if (selected) Text("✓")
    }
}

@KetoyEntryPoint
@KetoyComposable
fun PickerScreen() {
    var picked by remember { mutableStateOf("Alpha") }

    Column {
        LabeledRow(label = "Alpha", selected = picked == "Alpha", onSelect = { picked = "Alpha" })
        LabeledRow(label = "Beta",  selected = picked == "Beta",  onSelect = { picked = "Beta" })
    }
}
```

The callback captures the parent's `picked` state; tapping a row updates
it and the whole screen recomposes.

### Supported parameter types

A reusable component can take any of these:

| Kind | Example | Notes |
|------|---------|-------|
| **Primitives** | `String`, `Int`, `Boolean`, `Float`, `Long`, `Double` | Passed by value |
| **Compose value types** | `Dp`, `Sp`, `Color`, `TextUnit` | e.g. `padding: Dp`, `tint: Color` |
| **Theme colours** | `themeColor("name")` | Re-resolves per light/dark mode |
| **`data class`** | `VehicleOption(name, price)` | Constructed at the call site |
| **Lists** | `List<String>`, `List<VehicleOption>` | Literal or capability-returned |
| **Enums / sealed types** | `enum class Size`, `sealed interface State` | `when`/`is` works in the body |
| **Callback lambdas** | `onClick: () -> Unit`, `onSelect: (String) -> Unit` | Invoked via the component; captures allowed |
| **Content slots** | `content: @Composable () -> Unit` | The component places the children |
| **Item slots** | `item: @Composable (T) -> Unit` | For per-item content (list rows) |

```kotlin
data class VehicleOption(val name: String, val price: Int)

@KetoyComposable
fun VehicleRow(
    option: VehicleOption,                       // data class param
    selected: Boolean,                           // primitive
    accent: Color,                               // Compose value type
    onSelect: (VehicleOption) -> Unit,           // typed callback lambda
    trailing: @Composable () -> Unit,            // content slot
) {
    Row(modifier = Modifier.clickable { onSelect(option) }) {
        Text(option.name, color = if (selected) accent else Color.Gray)
        Text("$${option.price}")
        trailing()                               // component invokes the slot
    }
}
```

!!! warning "Not yet supported as a param"
    Drawable resources (`painterResource(R.drawable.X)`) can't be passed
    as a component parameter yet — reference them directly inside the
    component instead. Function-typed params must be lambdas (not
    top-level function references).

!!! note "Components in components"
    Reusable components can call other reusable components, and can be
    driven from a `forEach` loop (below). This is the primary way to keep
    KBC screens DRY.

## List iteration with `forEach`

Iterate a list and emit a composable per item. Works over literal lists
**and** lists returned by a host capability (so the host can own the
collection — add an item without republishing the bundle).

```kotlin
@KetoyComposable
fun VehicleList(options: List<VehicleOption>) {
    Column {
        options.forEach { option ->
            VehicleRow(option = option)             // reusable component per item
        }
    }
}

// forEachIndexed is supported too
items.forEachIndexed { index, item ->
    Text("${index + 1}. $item")
}
```

Per-item captures are correct — a `clickable { selected = it }` inside
the loop body re-snapshots the current element on each iteration.

!!! tip "forEach vs LazyColumn"
    `forEach` eagerly emits every row (best for short, known lists). For
    long/scrolling lists use `LazyColumn { items(list) { … } }`, which is
    virtualized. Both are available.

## Canvas / DrawScope

A full server-driven drawing surface. Write an ordinary `Canvas { … }`
with real Compose draw commands — shapes, paths, gradients, transforms,
and text — all sandboxed (no `nativeCanvas`, no `android.graphics`
escape).

```kotlin
@KetoyComposable
fun PieChart() {
    Canvas(modifier = Modifier.size(160.dp)) {
        // Geometry reads
        val radius = size.minDimension / 2f
        val mid = center

        // Shapes — Color, Offset, Size, Stroke, gradients all work
        drawArc(
            color = Color(0xFF6200EE),
            startAngle = 0f,
            sweepAngle = 270f,
            useCenter = false,
            style = Stroke(width = 24f, cap = StrokeCap.Round),
        )
        drawCircle(color = Color.White, radius = radius / 3f, center = mid)
    }
}
```

### What's available

- **Shapes** — `drawRect`, `drawCircle`, `drawLine`, `drawArc`,
  `drawRoundRect`, `drawOval`, `drawPath`. Each accepts a `color` **or**
  a `brush` (gradient) overload.
- **Value types** — `Offset(x, y)`, `Size(w, h)`, `CornerRadius(r)`,
  `Stroke(width, cap, join, pathEffect)`, `Color(0xAARRGGBB)`.
- **Paths** — build with `Path().apply { moveTo(...); lineTo(...);
  cubicTo(...); close() }` then `drawPath(path, brush = …)`.
- **Gradients** — `Brush.linearGradient(...)`,
  `verticalGradient`, `horizontalGradient`, `radialGradient`.
- **Path effects** — `PathEffect.dashPathEffect(...)`,
  `cornerPathEffect(...)`.
- **Transforms** — `rotate(deg) { … }`, `scale(...) { … }`,
  `translate(...) { … }`, `inset(...) { … }`, `clipRect { … }`,
  `clipPath(path) { … }` — each nests a draw block.
- **Geometry reads** — `size.width`, `size.height`, `size.minDimension`,
  `size.maxDimension`, `center.x`, `center.y`, plus `N.dp.toPx()`.
- **Numeric math** — `Float` / `Long` / `Double` arithmetic
  (`size.height / 2f`, `radius * 0.8f`) works inside the draw block.

### Text on a Canvas

Use the real `androidx.compose.ui.text.drawText` with a
`rememberTextMeasurer()` — idiomatic Compose, no Ketoy-specific import:

```kotlin
@KetoyComposable
fun LabeledCanvas() {
    val measurer = rememberTextMeasurer()
    Canvas(modifier = Modifier.size(200.dp)) {
        drawText(
            textMeasurer = measurer,
            text = "Hello",
            topLeft = Offset(16f, 16f),
        )
    }
}
```

## Layout & modifier additions

### Scroll

```kotlin
Column(modifier = Modifier.verticalScroll(rememberScrollState())) { … }
Row(modifier = Modifier.horizontalScroll(rememberScrollState())) { … }
```

### `Arrangement.spacedBy`

All three overloads, on `Column` / `Row` / `LazyColumn` / `LazyRow`:

```kotlin
Column(verticalArrangement = Arrangement.spacedBy(12.dp)) { … }
Column(verticalArrangement = Arrangement.spacedBy(12.dp, Alignment.Top)) { … }
```

### Per-corner rounded shapes

Works as a `shape =` argument **and** in `Modifier.clip/background/
border/shadow`:

```kotlin
Box(
    modifier = Modifier
        .clip(RoundedCornerShape(topStart = 16.dp, bottomEnd = 16.dp))
        .background(Color.LightGray),
)
```

### Dividers & theme colours

`HorizontalDivider` / `VerticalDivider` are now first-class adapters, and
[`themeColor("name")`](../theme-colors.md) lets a single bundle render
correctly in light **and** dark mode:

```kotlin
Surface(color = themeColor("backgroundColor")) {
    Column {
        Text("About", color = themeColor("textColor"))
        HorizontalDivider(color = themeColor("dividerColor"))
    }
}
```

## Compose-version decoupling

Adapter parameters are now encoded by **name** in the catalog's index
space, not by position in the consumer's Compose signature. A newer
Compose version that inserts or reorders a component parameter no longer
shifts your bundle's arguments — the font/colour/etc. still lands in the
right slot. You get this for free; nothing to configure.

## Migrating

Nothing to change in existing 0.3.x screens. To adopt the new features,
just write the Kotlin — typed ViewModels, `var` state, reusable
components, `forEach`, `Canvas` — in your `@KetoyComposable` source and
rebuild the bundle.
